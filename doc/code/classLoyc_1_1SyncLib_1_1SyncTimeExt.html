Remarks

Extension methods of ISyncManager for synchronizing the date/time types DateTime, DateTimeOffset and TimeSpan (plus DateOnly and TimeOnly on .NET 6+, but no target framework of Loyc.Essentials is currently new enough to include them).

The Sync methods choose a representation automatically (see SyncTime{SM}):

  • In plain-text formats (ISyncManager.IsPlainText), values are written as strings in the same formats Newtonsoft.Json uses: ISO-8601 for DateTime — in one of three forms according to its DateTimeKind — and DateTimeOffset, and constant ("c") format for TimeSpan.
  • In binary formats, values that fit in 64 bits are stored as integers: DateTime uses DateTime.ToBinary (which preserves the DateTimeKind) and TimeSpan uses TimeSpan.Ticks. A DateTimeOffset does not fit in 64 bits, so it is stored as a tuple of two integers: the Ticks of the local date/time, and the UTC offset in minutes.
  • When reading a plain-text format, the actual type of the field decides: a string is parsed as above, while an integer (or tuple) is decoded as in a binary format. This works because ISyncManager.GetFieldType returns the type of the field when the reader can determine it.

The other methods (SyncDateAsString, SyncTimeAsTicks, SyncTimeAsSeconds, etc.) each store values in one specific way, regardless of the data format.
